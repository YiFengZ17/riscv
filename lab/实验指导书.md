# 实验指导书：1024 位无符号整数运算

本文件说明如何开展实验。任务、接口、限制、提交文件和评分标准统一见 [实验任务书](实验题目.md)，本文件不新增考核要求。

## 一、安装与配置环境

本实验需要 **Java 运行环境和 RARS 1.6**。以下以 Windows 10/11 的常见 64 位电脑为例，软件均从官方链接下载。无需安装 Python、VS Code、Android Studio 或交叉编译工具链。

### 1.1 确认系统类型

打开 Windows“设置 → 系统 → 关于”，查看“系统类型”：Intel/AMD 的 64 位电脑选择 x64；ARM 电脑选择 aarch64/ARM64。不要把 ARM64 与 x64 混选。其他系统的安装入口见第 1.6 节。

### 1.2 检查是否已有 Java

按 Win+R，输入 `cmd` 并回车，在命令提示符中执行：

```text
java -version
```

若显示 Java 8 或以上版本，可先跳到第 1.4 节尝试启动 RARS；若提示“不是内部或外部命令”或“找不到 java”，继续安装。RARS 官方最低要求为 Java 8，本教程建议新装 Java 21 LTS。

### 1.3 下载并安装 Java

1. 打开 [Eclipse Temurin 官方下载页面](https://adoptium.net/temurin/releases/?version=21)。
2. 选择版本 **21 LTS**、操作系统 **Windows**、与电脑对应的架构。常见 Intel/AMD 电脑选 **x64**。
3. 包类型选择 **JRE**，下载安装格式 **.msi**。如果页面只提供 JDK，也可以安装 JDK；它包含运行 Java 程序所需的环境。不要下载源代码包。
4. 双击下载的 MSI，阅读许可，按向导安装。保留 **Add to PATH（添加到环境变量）**；可同时启用 **Associate .jar（JAR 文件关联）**。只运行 RARS 无需单独配置 JAVA_HOME。
5. 点击 Install，完成后点击 Finish。需要管理员权限时由机房管理员安装。
6. 关闭旧命令提示符，重新打开，再执行 `java -version`；应显示 `21.x` 版本信息。

若安装后仍找不到命令，先重开终端；仍不成功，则通过安装程序的修改功能确认 PATH 已启用，也可用 `where java` 查看实际调用的是哪个 Java。详细界面说明见 [Temurin 官方 Windows 安装文档](https://adoptium.net/zh-CN/installation/windows)。

### 1.4 下载并启动 RARS

1. 打开 [RARS 1.6 官方发布页](https://github.com/TheThirdOne/rars/releases/tag/v1.6)。
2. 在 **Assets** 中点击 `rars1_6.jar` 下载，也可点击 [JAR 官方直链](https://github.com/TheThirdOne/rars/releases/download/v1.6/rars1_6.jar)。不要选择 Source code。
3. 在自己的电脑上新建实验目录，例如 `C:\RiscVLab`，将 JAR 放入该目录。RARS 无需运行安装向导，JAR 也不需要解压。
4. 在命令提示符中依次执行：

```bat
cd /d C:\RiscVLab
java -jar rars1_6.jar
```

这里假定采用上面的示例目录；保存到其他位置时换成自己的路径。也可在 PowerShell 中先 `cd C:\RiscVLab`，再执行同一条 `java -jar` 命令。

看到 RARS 主窗口即启动成功。以后可使用同样命令打开；若已关联 JAR，也可双击启动。双击被压缩软件打开时，使用命令行启动即可。

### 1.5 配置 RARS 并新建源文件

1. Settings 中关闭 **64-bit** 模式，保持 **RV32**；允许伪指令。
2. 关闭“汇编整个目录”和“汇编所有打开文件”选项（以实际菜单为准），每次仅汇编自己的完整程序。
3. 选择 File → New，新建空白文件，再选择 File → Save As，将文件保存为 `bigint1024.s`。可与下载的 `rars1_6.jar` 放在同一实验目录，目录位置由自己选择。
4. 在资源管理器中显示文件扩展名，确认文件结尾为 `.s`，而非 `.s.txt`。

本实验从空白文件开始，不需要下载教师代码附件。数据区、main、运算子程序和测试组织均由自己编写。

### 1.6 macOS、Linux 与其他架构

在 [Temurin 下载页面](https://adoptium.net/temurin/releases/?version=21) 选择实际操作系统和架构。macOS 按 [官方 PKG 安装说明](https://adoptium.net/installation/macOS) 安装；Linux 按 [官方软件包安装说明](https://adoptium.net/installation/linux) 选择适合发行版的方法。ARM 电脑选择其对应构建，不能直接使用 Windows x64 MSI。

安装后在终端执行 `java -version`，确认可用。将相同的 `rars1_6.jar` 保存到自建实验目录，进入该目录执行 `java -jar rars1_6.jar`。后续 RARS 操作一致。本课程现有实测环境为 Windows。

## 二、从空白文件组织程序

先阅读 [实验任务书](实验题目.md)，确认接口与限制，再在自己创建的 `bigint1024.s` 中组织程序。可以按以下顺序开展：

1. 设计数据区：为 A、B 及和、差、积、商、余数分别分配存储空间，为三个状态值设置标签。
2. 编写 main：准备输入与参数、调用运算子程序、保存返回的状态，最后正常结束程序。
3. 编写 add1024、sub1024、mul1024、div1024，并按任务书遵守调用约定。
4. 先验证小数值，再逐步检查跨字进借位、2048 位乘积和全宽除法。

在报告中记录自己采用的内存标签，便于找到结果。函数返回后应及时保存 a0 中的状态，再准备下一次调用参数。

## 三、设计数据与算法

### 3.1 确认数据布局

1024 位由 32 个 32 位字组成。第 i 个字的地址为 `基址+4×i`，i 为 0–31；最后一个字的偏移是 124 字节，每个输入操作数共 128 字节。乘积则需要 64 个字、256 字节，最高字偏移为 252 字节；不能沿用其他结果的 32 字缓冲区。

例如 2^32+2 的最低字是 2，次低字是 1，其余 30 个字为零。输入可以直接定义在数据区，无需先实现几百位十进制数的键盘输入。

### 3.2 加法与减法

先用小数验证参数传递与结果保存，再检查跨字运算。区分两个字直接运算产生的进借位，以及叠加上一字进借位后产生的进借位。使用无符号含义分析比较条件。

### 3.3 乘法

可从二进制的部分积开始分析：根据乘数的各位决定是否累加相应移位后的被乘数。用小位宽在纸上推演，再考虑如何将移位、累加和进位传播到 64 字乘积缓冲区。

先验证零乘积、小数相乘，再检查任务书中 C²、M² 以及 2^1023×3 的高位。即使乘积较小，高 32 个字也应写成零。不能使用硬件 mul 系列指令。

### 3.4 除法

可先用小位宽在纸上演示按位长除法，再推广到 1024 位。明确每轮处理的位、余数的更新、商位的设置与终止条件。留意多字移位的最高进位，以及除零时所有输出字的处理。

上述内容为设计提示，完整算法和程序由学生自行完成。

## 四、汇编与运行自己的程序

1. 保存自己编写的 `bigint1024.s`，保持它为当前编辑页。
2. 选择 Run → Assemble，查看底部 Messages；存在错误时按行号定位并修改，保存后重新汇编。
3. 汇编成功后选择 Run → Go。看输出；如果使用内存结果，在 Execute 页的 Data Segment 查看各标签对应
4. 如果自己实现了打印，在底部 Run I/O 查的区域。

Messages 显示汇编与错误消息，Run I/O 接收程序的输入输出。仅在自己的程序实现了读取功能并等待输入时，才需要在 Run I/O 输入数据。未编写打印功能时，Run I/O 没有数值输出并不代表程序没有执行。

## 五、自行组织测试

任务书第五节已列出 10 组必测数据及预期结果，本指导书不重复列出。先用 100、7 检查基本调用流程，再测试边界情况。

1. 将一组输入按低字在前转换为 32 字布局，放入自己的数据区。
2. 初始化输出缓冲区；调试时可使用非零初值，便于发现漏写。
3. 运行程序，逐字核对和、差、积、商、余数，检查加法、减法、除法的三个状态值，以及乘法返回值是否为 0。
4. 检查 A、B 是否保持不变，以及调用前后的保存寄存器和栈是否一致。
5. 记录实际结果与预期结果。修改输入后重新保存、Assemble、Go。

也可以自行编写批量测试逻辑。无论采用哪种方式，完整程序都由自己编写；不依赖教师测试入口，也不要求输出固定的 PASS/FAIL 格式。

数学表达式与内存表示要区分：任务书中的 2^992 表示一个数值，不能原样当成 32 位 `.word` 常量。它对应第 31 个字为 1（从第 0 个字计数），其余字为零；2^1023 对应最高字为 0x80000000。

## 六、单步调试与检查

### 6.1 查看内存结果

在 Execute 页打开标签表（Labels/Symbol Table），定位自己定义的输出标签。Data Segment 选择十六进制数值显示，关闭 ASCII，按连续 32 个字检查和、差、商、余数；乘积须检查连续 64 个字。

缓冲区地址和状态字位置取决于自己的数据布局，没有统一的固定偏移。每个字按无符号数解释；不要把低字在前的内存序列直接当作高位在前的十六进制整数阅读。

### 6.2 观察寄存器与断点

- Assemble 后在 Text Segment 的 Bkpt 列勾选目标指令，再用 Go 运行至断点。
- Run → Step 一次执行一条机器指令；伪指令可能展开为多条。
- 在右侧 Registers 观察指针、循环计数、进借位、部分积及商/余数状态。
- 比较函数入口和返回前的 sp、s0–s11，检查保存恢复；检查访存地址是否在对应缓冲区内。
- 1024 位乘除法指令较多，可在关键位置设置断点，无需从头逐条执行。

### 6.3 常见现象

| 现象 | 排查方向 |
|---|---|
| 标签未定义 | 检查 main、函数名称、数据标签是否一致 |
| 标签重复或多个 main | 关闭整目录/全部文件汇编，检查自己的标签定义 |
| 结果未写入或只改了低位 | 检查输出指针、循环次数和是否覆盖所有输出字（乘积 64 字，其余结果各 32 字） |
| 普通输入正确，边界错误 | 检查无符号比较、进借位传播和移位最高进位 |
| 输入被改动 | 检查是否误把输入地址作为输出地址或越界写入 |
| 调用后跳转异常 | 检查 ra、栈帧和保存寄存器 |
| 运行长时间不结束 | 检查循环终止条件、除零分支及乘除法算法 |
| Run I/O 没有打印 | 确认自己是否编写了打印逻辑；也可直接检查内存 |
